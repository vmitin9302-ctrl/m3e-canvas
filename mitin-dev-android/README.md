# MITIN DEV — Android 0.2: Demo + Internal

Самостоятельный Android/Gradle root. Открывайте **эту папку** в Android Studio. Код редактора M3E Canvas не является зависимостью приложения. Варианты demo и internal изолированы по source sets, application ID, permissions и хранилищу.

## Сборка

JDK 17, Gradle 8.13 (wrapper + SHA-256), AGP 8.13.2, Kotlin/Compose compiler 2.2.20, Compose BOM 2025.10.01, Material 3 Expressive 1.5.0-alpha07 (явно закреплён: в stable 1.4 Expressive API ещё internal). `compileSdk/targetSdk=36`, `minSdk=26` (Android 8.0). Зависимости закреплены в Gradle, динамических версий нет. Release variant отключён; доступны `demoDebug` и `internalDebug`.

```sh
./gradlew --no-daemon assembleDemoDebug testDemoDebugUnitTest lintDemoDebug
./gradlew --no-daemon connectedDemoDebugAndroidTest
python3 scripts/check_design.py
```

APK: `app/build/outputs/apk/demo/debug/app-demo-debug.apk`. Изолированный CI: `../.github/workflows/android-demo.yml`, обычный pull_request, бесплатный стандартный runner, contents:read, без production secrets. Он собирает APK, запускает unit/lint и реальные Compose/UIAutomator-тесты на Android 15/API 35, затем повторяет их при системном шрифте 160%. Сохраняет APK, SHA-256, XML/HTML-отчёты и скриншоты запущенного приложения. Android SDK локальной Work-среды отсутствует, поэтому основание для результата — завершённый CI, не наличие YAML.

Совместимость: [AGP 8.13](https://developer.android.com/build/releases/agp-8-13-0-release-notes), [Material 3](https://developer.android.com/jetpack/androidx/releases/compose-material3), [контрольные суммы Gradle](https://gradle.org/release-checksums/).

## Локальный демонстрационный сценарий

Клиент: Welcome → Создать проект → Тип → сценарный AI-бриф → Функции и бюджет → Проверка → Сохранить демозаявку → локальное подтверждение → Главная → Проект → Этап → Демо → нативный макет.

Владелец: кнопка «ДЕМО» → «Я владелец» → Заявки → карточка новой заявки → Создать демопроект → Изменить этап. Затем «ДЕМО» → клиент → демо-вход → новый проект: изменения видны в том же хранилище.

Переключатель ролей предназначен только для демонстрации, не является авторизацией. Пример кабинета после договора (проект 1 из заявки 1042) явно отделён от новой заявки. Новая заявка сама не создаёт проект; новый проект не получает цену, оплату, согласованный срок или готовое демо.

## Локальные данные и ограничения

Один `DemoRepository` для обеих ролей, неизменяемые снимки + Mutex, сохранение JSON в приватных SharedPreferences вне UI thread. UI публикует изменения после успешной записи. Создание проекта по одной заявке идемпотентно. Текст черновика и навигация переживают пересоздание Activity через rememberSaveable. Сброс демо удаляет сохранённые изменения; очистка данных Android удаляет всё, включая черновик задачи.

Только вымышленный Алексей Смирнов и синтетические проекты. Поля ограничены по длине, хранилище — 100 заявками и последними 30 сообщениями проекта. Суммы подготовленного проекта являются примерами. `budget_range`: under_10k / 10_20k / 20_40k / 40_70k / 70k_plus / unknown. Статусы: not_started / in_progress / waiting_client / completed. Эти значения покрыты unit tests.

Работают локальные решения по демо, правки, проектный чат, фильтр заявок и смена статуса заявки. Сообщения явно добавляются **локально**, без доставки. В demo APK отсутствует permission INTERNET; нет сетевого API-клиента, WebView, аналитики, AI-вызовов, credentials или уведомлений. Backup отключён. Шрифты системные, иконки упакованы в APK.

В demo загрузка файлов, настоящая поддержка, платежи и авторизация не реализованы. Демо сайта — самостоятельный нативный макет, не браузер и не готовый клиентский сайт. Все 52 утверждённых экрана сохранены в исходном Canvas JSON и [карте покрытия](docs/DESIGN_COVERAGE.md); дополнительные целевые экраны не выдаются за реализованные.

## Установка

1. Скопируйте `MITIN-DEV-demoDebug.apk` на телефон с Android 8.0 или новее.
2. Откройте APK и разрешите установку из выбранного приложения файлов/браузера, если Android попросит. После установки разрешение можно отключить.
3. Откройте «MITIN DEV · Демо». Интернет и аккаунт не нужны.

Через USB: `adb install -r MITIN-DEV-demoDebug.apk`.

Это debug-подпись временного CI, не ключ выпуска. Если другая демосборка с этим package ID была подписана другим ключом, сначала удалите её (локальные демоданные удалятся). Production deploy, merge и публикация в магазинах не выполняются.


## Internal: настоящий сетевой кабинет

`internalDebug`, package `dev.mitin.app.internal`, название **MITIN DEV · Тест**. Login → собственный профиль → сессии → отзыв / выход / выход со всех устройств используют HTTPS API. Вход владельца без MFA закрыт сервером; переключателя роли нет. `DemoRepository` не компилируется в этот APK. Ошибки API не заменяются mock-успехом.

```sh
./gradlew --no-daemon \
  -PmitinApiBaseUrl=https://localhost:8443/ \
  -PmitinCaPem=/absolute/path/to/mitin-local-ca.pem \
  assembleInternalDebug testInternalDebugUnitTest lintInternalDebug
```

Разрешён только явно заданный локальный origin. Без параметра URL показывается «Тестовый сервер не настроен»; fallback на production отсутствует. PEM — **публичный сертификат** локального CA, не private key. Default публичный unconfigured CA не даёт доступа к серверу; его private key не сохранялся. TLS/hostname проверяются, redirects и автоматические повторы auth POST выключены. Access только Bearer, refresh только JSON.

Backend запускается отдельно владельцем приватного репозитория по `docs/MITIN_DEV_MOBILE_INTEGRATION.md` в его feature-ветке. В публичный репозиторий backend-код и DB credentials не копируются. На компьютере с запущенным тестовым API выполните `adb reverse tcp:8443 tcp:8443`; на телефоне используйте установленный собственный локальный test CA либо соберите APK с его публичным сертификатом. CI-сервер прекращает существование после завершения job. APK не является приложением с постоянно доступным тестовым сервером.

Настоящие network/UI/process E2E находятся в `src/androidTestInternal`. Их запускает приватный CI с PostgreSQL 18 и checkout Android на точном SHA. Public workflow сохраняет demo regression, компилирует обе сборки и проверяет unit/lint. Instrumentation test APK отдельно содержит синтетические fixtures; его не распространяют как приложение. Завершённые проверки и точные SHA фиксируются в [NETWORK_VERIFICATION.md](docs/NETWORK_VERIFICATION.md).

## Токены и ошибки

Один SessionManager живёт в Application. Пароль не сохраняется; access находится в памяти. Refresh хранится в AES-GCM ciphertext в noBackupFilesDir/AtomicFile, ключ — Android Keystore. Нет plaintext fallback, повторения IV и обязательного StrongBox. Backup/data transfer отключены.

Перед refresh атомарно сохраняется маркер незавершённого обмена без старого токена. Параллельные запросы ждут одного обмена. Новая пара публикуется после сохранения; epoch/generation защищают от позднего ответа после logout или другого входа. Потерянный ответ, прерывание процесса и ошибка сохранения требуют повторного входа, без скрытого replay строгой серверной ротации. После перезапуска профиль обязательно подтверждает сервер.

Logout сначала очищает локальное состояние и отменяет запросы. UI различает локальную очистку и подтверждённый серверный отзыв. Offline logout не обещает, что доступ на другом устройстве закрыт. GET имеет максимум один повтор после успешного refresh; POST не повторяется автоматически.

Локальный срок access отсчитывается от начала запроса login/refresh, а не от получения ответа. Запас перед истечением — до 5 секунд (для короткого test TTL — четверть срока). Это учитывает транспорт, запись хранилища и секундную точность серверного NumericDate. Перед изменяющей операцией менеджер получает пригодный access; сам POST повторно не отправляется. Случайная задержка сети всё равно может привести к отказу сервера — клиент не обещает абсолютного совпадения часов.

Auth-клиент не сохраняет простаивающие TLS-соединения в пуле: после завершения запроса соединение закрывается. Это уменьшает риск повторного использования закрытого сервером keep-alive соединения после редактирования формы или ухода в фон при строгом запрете повторов POST. Цена — дополнительные TLS handshake; это осознанный компромисс небольшого тестового auth-контура, не настройка будущих проектных загрузок.

## Полный визуальный стиль

Весь интерфейс использует общие Material 3 Expressive компоненты: тёмный графит, холодные фиолетовые/голубые акценты, тонкие градиентные обводки, объёмные контейнеры, мягкие углы и нативная эмблема M. Это применяется к welcome, брифу, бюджету, заявкам, проектам/этапам, owner и сетевым экранам входа/профиля/сессий — не только к заставке. Native splash и экран реального восстановления используют ту же эмблему. Нет искусственной задержки загрузки или нарисованных процентов.

Макеты состоят из Compose-компонентов; нет WebView/скриншотов вместо UI. Вертикальная прокрутка и адаптивная высота сохраняют доступность при 160% шрифте и клавиатуре. Все 52 исходных Canvas-экрана сохранены как целевой дизайн; изменение общей темы не означает реализацию всех будущих функций.

Навигация internal: **Готовые проекты / Обсудить с AI / Мой кабинет**. AI и портфолио пока явно не подключены. До публичного выпуска они должны использовать существующий серверный AI-бриф/бюджет/подтверждение CRM-заявки с дедупликацией и публичный каталог кейсов. Auth-only сборка не готова к публикации.

Новые зависимости: OkHttp 5.3.2 (только internal), MockWebServer/okhttp-tls 5.3.2 (только testInternal), core-splashscreen 1.0.1. Остальной стек не обновлялся. Runtime/test transitives перечисляет `writeDependencyInventory`; полный OSV audit выполняется в приватном CI, без ignores. Debug signing key временный; выпускной ключ не создаётся.
